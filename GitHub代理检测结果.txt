  三、关键结论与风险提示
------------------------------------------------------------
  1) 本机直连 raw.githubusercontent.com 属间歇性可用（专项抽测 8 次成功 3 次，失败时 6 秒超时），
     不能作为可靠通道，应以实测可用的加速代理为主要拉取方式。
  2) gh-proxy.org / gh-proxy.com 在本机为「连接被拒」；其中 gh-proxy.org 的 DNS 被解析为
     127.0.0.1，属本机解析异常，因此「云端规则前缀统一用 https://gh-proxy.org/」在本机无法工作，
     需先修正 DNS 解析或改用本文中实测可用的前缀。
  3) hosts 中已写入的 GitHub 直连 IP（140.82.112.3 / 185.199.108.133 等）实测无效。
  4) github.akams.cn 域名可达但对 raw 路径返回 404，只能用于 github.com/... 形式，不可作 raw 前缀。
  5) hub.gitmirror.com、raw.gitmirror.com 域名已解析不到，属失效域名。
  6) ghproxy.cfd 返回的是盗版体育直播站页面，与 GitHub 加速无关，且来源不可信，禁止使用。
  7) ghproxy.link 返回的是导航页（Vue 单页），不是可用的文件代理。
     gh-proxy.net 返回的是 HTML 跳转页（window.location.replace 到第三方地址），同样不是真实文件代理，
     且存在引流风险，禁止使用。
  8) 判定原则：仅 HTTP 200 不足以证明可用，必须校验 Content-Type 非 HTML 且返回内容为真实文件；
     本次实测已据此剔除 ghproxy.cfd、ghproxy.link、gh-proxy.net、gh.con.sh 等假可用项。
  9) 备用方案：jsDelivr CDN（https://cdn.jsdelivr.net/gh/用户/仓库@版本/路径），本次实测可取到真实文件，
     但仅支持仓库内文件，不支持 release 与 clone。
